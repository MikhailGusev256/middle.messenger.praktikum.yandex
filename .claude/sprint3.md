# Функциональные требования
## 1. Роутинг приложения
- Реализуйте роутер согласно имплементации из уроков.
- Настройте маршруты для всех страниц приложения:
  - / — страница входа
  - /sign-up — страница регистрации
  - /settings — настройки профиля пользователя
  - /messenger — чат
  - /404
  - /500
- Реализуйте переходы между страницами по клику. Например, кликнув по ссылке «Вернуться» на странице настроек, вы возвращаетесь к списку чатов.
- Обеспечьте корректную работу истории браузера: навигация по кнопкам «Назад» и «Вперёд» должна функционировать без сбоев.
- При перезагрузке (например, с помощью F5/⌘+R) пользователь должен остаться на той же странице.
- В DOM одновременно может быть активна только одна страница, поэтому при переходе на новую убедитесь, что предыдущая удалена.
## 2. Интеграция клиента с HTTP API
- Внедрите регистрацию, вход и выход из системы.
- Реализуйте управление профилем пользователя (изменение данных, аватара и пароля) и работу с чатами (получение списка, создание новых чатов, а также возможность добавить и удалить пользователя).
- После регистрации пользователь должен перенаправляться на страницу чата.
  Документацию по API вы найдёте [здесь](https://ya-praktikum.tech/api/v2/swagger/#/).                
  При работе с API используйте только тестовые данные: никаких реальных имён, email или телефонов. Добавьте простую проверку авторизации в роутер, чтобы перенаправить неавторизованных пользователей.
## 3. Класс для работы с запросами
- Используйте только Promise и XHR. Fetch, axios и аналогичные библиотеки запрещены.
- Реализуйте поддержку методов GET, POST, PUT и DELETE.
- Настройте обработку query string для GET и body для остальных методов.

## Возможно понадобится доделать, чтобы логин работал без ручных настроек браузера — Cross-site cookies
Проблема: фронт и API на разных доменах → кука `authCookie` третья-сторонняя. Chrome по умолчанию её режет: `signin` возвращает 200, но кука не сохраняется, и `GET /auth/user` падает `401 Cookie is not valid`. «Разрешить third-party cookies» в Chrome — костыль только на своей машине; у проверяющего/в CI логин снова упадёт. Решение — сделать запросы same-origin через прокси (нужны обе среды, они делают одно и то же):
- [ ] `vite.config` — `server.proxy`: проксировать `/api/v2` → `https://ya-praktikum.tech/api/v2` для `npm run dev` (dev-сервер, в билд не попадает).
- [ ] `netlify.toml` — redirect-rewrite (статус `200`, не `301`): `/api/v2/*` → `https://ya-praktikum.tech/api/v2/:splat` для задеплоенного сайта.
- [ ] `apiUrl` в `src/api/constants.ts` сделать относительным (`/api/v2`) вместо полного URL — один и тот же код для dev и прода.
